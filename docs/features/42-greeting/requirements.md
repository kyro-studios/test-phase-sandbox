# 要件定義書: 名前を入力すると挨拶を表示する

## 1. 目的

利用者が名前を入力すると、その名前を使った挨拶を画面に表示する。挨拶の文はサーバーが作り、画面はその結果を表示する。名前が空のときや長すぎるときは、利用者に誤りを伝える。

この機能は、仕組みの動作確認 (受け入れ基準の作成) のための小さな機能である。

## 2. 範囲

### 2.1 この機能で扱うこと

- 名前を入力して、挨拶を表示する画面
- 名前から挨拶の文を作る、サーバーの API
- 名前の入力の誤り (空、長すぎる) を伝えること

### 2.2 この機能で扱わないこと

- 名前や挨拶の保存 (履歴の表示を含む)
- ログインや、利用者ごとの表示の切り替え
- 時刻や言語による、挨拶の文の切り替え
- 既存の画面 (サーバーの稼働状況の確認など) からの導線

## 3. 用語

| 用語 | 意味 |
| --- | --- |
| 利用者 | アプリケーションを使う人。ログインは要らない |
| 名前 | 利用者が入力する文字列。前後の空白を除いたものを、名前として扱う |
| 挨拶 | `こんにちは、<名前> さん` の形の文 (例: 名前が `山田` なら `こんにちは、山田 さん`) |
| 文字数 | 名前の文字の数。Unicode のコードポイントの数で数える |

## 4. 機能要件

- FR-1: 挨拶の画面に、名前の入力欄と、挨拶を求めるボタン (`挨拶する`) を表示する
- FR-2: 利用者が名前を入力してボタンを押すと、挨拶を画面に表示する
- FR-3: 挨拶の文は、サーバーの API が名前から作る。画面は、API が返した挨拶をそのまま表示する
- FR-4: 名前は、前後の空白を除いてから扱う。挨拶の文にも、空白を除いた名前を使う
- FR-5: 前後の空白を除いた名前が空のときは、`名前を入力してください` と表示し、挨拶は表示しない
- FR-6: 前後の空白を除いた名前の文字数が 21 文字以上のときは、`名前は 20 文字以内で入力してください` と表示し、挨拶は表示しない。20 文字ちょうどは受け付ける
- FR-7: サーバーの API も、FR-4 から FR-6 と同じ決まりで名前を確かめる。画面を通さずに API を呼んだときも、誤りの名前からは挨拶を作らず、誤りであることと、FR-5 か FR-6 と同じ文言を返す
- FR-8: もう一度ボタンを押したときは、前に表示した挨拶や誤りを、新しい結果で置き換える

## 5. 非機能要件

- NFR-1: 名前や挨拶を、サーバーにもブラウザーにも保存しない
- NFR-2: 名前の入力欄は、支援技術 (スクリーンリーダーなど) から、何を入力する欄か分かるようにする。誤りの表示も、支援技術から読み上げられるようにする
- NFR-3: サーバーに接続できないときは、`挨拶を取得できませんでした` と表示する

## 6. 前提

- 利用者は、ブラウザーでアプリケーションを使う
- この機能は、このリポジトリの 3 つ目の機能で、アプリケーションのプロジェクトの土台はすでにある
- この機能は、仕組みの動作確認のための小さな機能である
