# 要件定義書: サーバーの稼働状況の確認

## 1. 目的

アプリケーションのサーバーが動いているかを、利用者と外部の監視の仕組みが確かめられるようにする。そのため、稼働状況を返す API と、その結果を表示する画面を用意する。

## 2. 範囲

### 2.1 この機能で扱うこと

- サーバーの稼働状況を返す API
- 稼働状況を表示する画面

### 2.2 この機能で扱わないこと

- データベースなど、サーバーが依存するものごとの詳しい状態
- 稼働状況の履歴の保存
- 稼働状況が変わったときの通知
- 利用者の認証

## 3. 用語

| 用語 | 意味 |
| --- | --- |
| 利用者 | アプリケーションを使う人。ログインしているかどうかは問わない |
| 稼働状況 | サーバーが要求に応答できる状態かどうか |
| 稼働状況の API | 稼働状況を返す API |
| 稼働状況の画面 | 稼働状況の API の結果を表示する画面 |

## 4. 機能要件

- FR-1: 稼働状況の API は、サーバーが要求に応答できるとき、正常に動いていることを表す結果を返す
- FR-2: 稼働状況の API の結果には、状態 (正常に動いていることを表す `ok`) と、サーバーが応答した時刻 (UTC の ISO 8601 形式) を含める
- FR-3: 稼働状況の API は、ログインしていない利用者や、外部の監視の仕組みからも呼び出せる
- FR-4: 稼働状況の画面を開くと、稼働状況の API を呼び出し、結果の状態と時刻を表示する
- FR-5: 稼働状況の API に接続できないときや、API がエラーを返したときは、稼働状況の画面に「サーバーに接続できません」と表示する
- FR-6: 稼働状況の画面には「再読み込み」のボタンを置く。押すと、稼働状況を取得し直して、表示を更新する

## 5. 非機能要件

- NFR-1: 稼働状況の API は、データベースなどの依存するものに接続せずに応答する。依存するものの障害で、サーバー自身の稼働を確かめられなくならないようにするため
- NFR-2: 稼働状況の API は、要求を受けてから 1 秒以内に応答する
- NFR-3: 稼働状況の API の結果には、サーバーの内部の情報 (バージョン、構成、環境変数など) を含めない

## 6. 前提

- 利用者は、ブラウザーでアプリケーションを使う
- この機能は、このリポジトリの最初の機能で、アプリケーションのプロジェクトの土台はまだ無い
- この機能は、仕組みの動作確認のための小さな機能である
